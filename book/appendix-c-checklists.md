# Приложение C. Чек-листы и шаблоны

Это приложение можно использовать как быстрый справочник во время работы с проектом.

## Чек-лист перед созданием спецификации

- понятна цель фичи;
- известна аудитория;
- есть границы работы;
- есть то, что не входит в работу;
- известны ограничения стека;
- есть хотя бы один проверяемый результат;
- понятно, какая фаза дорожной карты реализуется;
- не требуется секрет или доступ, которого нет в локальной среде.

## Чек-лист перед реализацией

- `requirements.md` создан;
- `plan.md` создан;
- `validation.md` создан;
- спецификация закоммичена;
- агенту переданы ссылки на файлы, а не длинная история чата;
- текущая ветка чистая или понятна;
- границы фичи не спорят с `tech-stack.md`;
- в плане нет несвязанных рефакторингов.

## Чек-лист перед запросом на слияние

- все изменённые файлы связаны с фичей;
- обязательные факты из `validation.md` проверены;
- проваленные факты явно перечислены;
- отложенные факты имеют причину;
- новые хуки и MCP-серверы ревьюились;
- секреты не попали в спецификации, логи и память;
- `CHANGELOG.md` обновлён, если проект его ведёт;
- дорожная карта обновлена или есть причина не обновлять её в этой ветке.

## Шаблон запроса на слияние

```markdown
## Спецификация

- Папка: `specs/YYYY-MM-DD-feature-name/`
- Фаза дорожной карты:

## Что изменено

- 

## Факты проверки

- [ ] `npm run typecheck`
- [ ] `npm test`
- [ ] 

## Непроверенные или отложенные факты

- 

## Изменения вне границ фичи

- Нет / перечислить:

## Что ревьюеру проверить особенно внимательно

- 
```

## Шаблон ретроспективы

```markdown
# Ретроспектива SDD

## Что спецификация описала правильно

## Что агенту пришлось вывести самому

## Что поймала проверка

## Какие факты были слабыми

## Что перенести в QWEN.md или specs/

## Что убрать из процесса
```

## Чек-лист для новой сессии после `/clear`

- агент прочитал `QWEN.md` или `AGENTS.md`;
- агент прочитал `mission.md`;
- агент прочитал `tech-stack.md`;
- агент прочитал нужную папку фичи;
- агент знает, какие файлы нельзя менять;
- агент знает, какие команды проверки ожидаются;
- агент остановится после отчёта, если задача только исследовательская.

## Минимальный запрос для ревью реализации

```text
/clear
Прочитай @QWEN.md, спецификацию текущей фичи и git diff.
Сравни реализацию с requirements.md, plan.md и validation.md.
Покажи:
- совпадения;
- расхождения;
- непроверенные факты;
- изменения вне границ фичи.
Файлы не изменяй.
```

## Минимальный запрос для перепланирования

```text
/clear
Прочитай @specs/mission.md, @specs/tech-stack.md, @specs/roadmap.md,
недавние спецификации фич и @CHANGELOG.md.
Покажи, что нужно обновить перед следующей фазой.
Файлы не изменяй, пока я не одобрю.
```
