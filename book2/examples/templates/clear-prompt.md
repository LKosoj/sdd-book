# Минимальный запрос для ревью реализации после `/clear`

Используется в production-сценарии, когда нужно получить независимое сравнение кода со спецификацией без переноса истории чата. Расширяет [запрос для ревью из первого тома](../../../book/appendix-c-checklists.md) шагами для контракта, теневых спецификаций и метрик.

```text
/clear
Прочитай @QWEN.md, спецификацию текущей фичи, @validation.md
и git diff против main.
Сравни реализацию с requirements.md, plan.md и validation.md.

Покажи:
- совпадения;
- расхождения;
- непокрытые факты (по новому контракту JSON Schema, если есть);
- изменения вне границ фичи;
- теневые спецификации или few-shot, которые повлияли на интерпретацию;
- guard-метрики и правила красной кнопки, которых не хватает.

Файлы не изменяй. Если для проверки нужен новый counterexample
или мутант — предложи его в виде минимального JSON, а не действия.
```

## Когда использовать

- Перед PR — собрать ясный список расхождений до того, как ревьюер откроет diff.
- Перед merge — проверить, что после последних правок Имплементор не сломал contract.
- В incident response — получить независимое чтение спецификации без памяти инцидента.
