# A/B-матрица пар ярусов

Расширение `tribunal/`-примера. Тот же дуэт спецификация + контрпримеры
прогоняется по нескольким парам Имплементор/Верификатор и фиксирует, какие
пары пропускают спецификацию, а какие — рубят. Так из единственного вердикта
вырастает таблица, по которой видно, **зависит ли решение от выбора ярусов**.

## Что моделирует пример

Один и тот же `judge()` из `scripts/run_duel.py` подмешивается двумя разными
формами доказательства, в зависимости от яруса Имплементора:

- `local-coder` (минимальный ярус) → `evidence_format: minimal_form`,
  доказательство — короткий `diagnostic_code`.
- `frontier-reviewer` (расширенный ярус) → `evidence_format: extended_form`,
  доказательство — структура `evidence_by_invariant: {<id>: {status, value}}`
  без короткого кода.

Верификаторы умеют принимать только заранее объявленные форматы:

- `local-coder` распознаёт только `minimal_form`;
- `frontier-reviewer` — и `minimal_form`, и `extended_form`.

Из-за этого пара C2 (сильный Имплементор + слабый Верификатор) падает: сильный
Имплементор отдаёт развёрнутые инварианты, а слабый Верификатор их не понимает.
Остальные три пары проходят. Именно это и называется
`signal: tier_dependent_spec` — спецификация чувствительна к выбору ярусов.

## Структура

```
matrix/
├── tiers.json                  конфиг ярусов и пар
├── matrix.example.json         канонический вывод (для diff в smoke)
└── README.md
```

Скрипт лежит рядом с дуэтом: `scripts/matrix.py`.

## Как запустить

```bash
cd book2/examples/tribunal
python3 scripts/matrix.py \
  --spec specs/autoscale_spec.yaml \
  --cases cases/ \
  --tiers matrix/tiers.json \
  --out out/matrix.json
```

Без аргумента `--pairs` прогоняются все четыре пары. Чтобы прогнать
подмножество, передайте список `impl/verifier`:

```bash
python3 scripts/matrix.py ... --pairs frontier-reviewer/local-coder
```

## Что в `out/matrix.json`

- `summary.signal` ∈ `{tier_dependent_spec, uniform_pass, uniform_fail}`.
- `summary.pass_pairs` / `summary.fail_pairs` — `pair_id` по корзинам.
- `summary.diverging: true` ⇔ есть и PASS-, и FAIL-пары.
- `pairs[*].cases[*]` — детальная разбивка по контрпримерам с `reasons`.

## Код возврата

- `0` — все пары проходят (uniform_pass) **или** все падают (uniform_fail).
- `1` — расхождение между парами (diverging=true), то есть как раз учебно
  интересный случай `tier_dependent_spec`.

В `smoke_all.sh` вызов обёрнут в `expect_fail` — мы хотим, чтобы пример именно
давал расхождение, иначе вся история про A/B-матрицу теряет смысл.

## Когда такая матрица полезна на проекте

- Решаете, стоит ли платить за дорогую пару ярусов на этой спецификации.
- Хотите формальное доказательство, что слабая пара ярусов «не видит»
  определённый класс нарушений.
- Хотите перед инцидентом увидеть, на каких именно парах развалится решение,
  и приложить эту таблицу к judgment.
