# Приложение B. Локальный DataLakeHouse-стек

Учебный стек выбран так, чтобы пройти весь SDD Data-цикл без внешнего кластера.
Он не имитирует боевой контур полностью, но сохраняет главное: источники, модели,
контракты, тесты и доказательства.

## Компоненты

- Стандартная библиотека Python генерирует синтетические CSV.
- DuckDB исполняет локальные аналитические запросы.
- dbt-core управляет DAG, материализациями, тестами и lineage.
- dbt-duckdb подключает dbt к DuckDB.
- Qwen Code читает спецификации, предлагает SQL и помогает проводить ревью.

## Почему не Spark сразу

Для первого прохода важнее увидеть связь:

```text
спецификация -> контракт -> dbt-модель -> проверочный факт -> отчёт ревьюера
```

Если локальный пример не держит grain, политику PII и дрейф контракта, боевой
кластер только ускорит ошибку. Spark, Trino, Iceberg или Delta Lake нужны, когда
уже есть устойчивый путь контракта.

## Сопоставление с боевым контуром

| Локально | Аналог в боевом контуре |
|---|---|
| CSV raw-файлы | зона посадки в хранилище объектов |
| база DuckDB | вычислительный слой warehouse/lakehouse |
| dbt-duckdb | dbt-адаптер для warehouse |
| `models/schema.yml` | контракт модели и набор проверок качества |
| singular-тесты dbt | проверки контракта и качества данных |
| Markdown с проверочными фактами | пакет доказательств релиза |

## Что не моделируется

- реальные секреты и доступы;
- потоковая загрузка;
- распределённое исполнение;
- доступ по ролям;
- боевой планировщик;
- процесс юридического подтверждения.

Эти темы можно обсуждать в заметках о боевом контуре, но не нужно внедрять в первый
учебный проход. Иначе студент начнёт решать инфраструктуру раньше смысла данных.
