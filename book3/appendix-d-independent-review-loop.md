# Приложение D. Независимый цикл ревью

Этот учебник нельзя считать готовым только потому, что автор расширил главы и
получил зелёный `dbt build`. Финальный контроль должен выполнять независимый
ревьюер: человек или сабагент, который сравнивает третий том с первым и ищет
не косметические замечания, а разницу в учебном уровне.

## Зачем нужен цикл

Автор текста быстро привыкает к собственным пропускам. Если глава говорит
«создайте проверочные факты», автор помнит, что это значит, но новый студент
может не понять, где файл, какая команда, какой ожидаемый результат и что делать
при провале. Первый том хорош именно тем, что много раз закрывает такие
разрывы: мотивация, пример, антипример, проверка, рубрика, типичная ошибка.

Поэтому финальный процесс:

```text
черновик -> локальные проверки -> независимое ревью -> список пробелов -> правки -> повторное ревью
```

Цикл заканчивается не по ощущению автора, а по вердикту ревьюера: третий том не
ниже первого по критическим категориям.

## Роль независимого ревьюера

Ревьюер работает в режиме только чтения. Он не редактирует файлы и не исправляет текст.
Его задача:

- прочитать `book/README.md` и показательные главы первого тома;
- прочитать `book3/README.md`, все части, приложения и запускаемый пример;
- сравнить не тему, а качество обучения;
- найти места, где `book3` слабее;
- дать конкретные доработки с файлами и причинами.

Ревьюер не должен принимать аргумент «тема сложнее» как оправдание слабого
объяснения. Если тема сложнее, учебник должен объяснять её яснее.

## Рубрика паритета

Оценка идёт по категориям:

| Категория | Что означает паритет |
|---|---|
| Учебный путь | читатель понимает порядок прохождения без автора |
| Мотивация | каждая тема объясняет, какой риск закрывает |
| Практика | после главы остаётся конкретный артефакт |
| Проверка | факты имеют команды, SQL или шаги ревьюера |
| Примеры | есть плохой и хороший вариант там, где возможна путаница |
| Запускаемость | пример проходит полный smoke/build |
| Контракты | specs, ODCS/ODPS, dbt-тесты и проверочные факты согласованы |
| Ревью | роль ревьюера отделена от роли автора |
| Преподавание | заметка для преподавателя и рубрики позволяют провести курс |
| Честность | README не обещает того, чего нет в файлах |

Критическая категория не может быть ниже первого тома. Некритические отличия
допустимы, если ревьюер явно объяснил, почему они не мешают v1.0.

## Промпт для сабагента

```text
Ты независимый ревьюер учебника.

Задача: сравнить book3 с book и определить, достиг ли book3 уровня первого
тома как самостоятельный учебник.

Работай в режиме только чтения. Ничего не редактируй.

Проверь:
- полноту учебного пути;
- глубину объяснений;
- качество практических заданий;
- запускаемый пример;
- связность specs/contracts/tests/validation;
- материалы преподавателя;
- практический зачёт;
- честность README/CHANGELOG.

Верни:
1. краткую оценку book;
2. краткую оценку book3;
3. вердикт: на уровне / ниже уровня;
4. категории, где book3 ниже;
5. конкретные файлы и доработки;
6. минимальный список изменений для следующего цикла.
```

## Как применять результат

После ревью автор не спорит с каждым замечанием. Сначала он сортирует замечания:

- **критический блокер** — без этого уровень ниже первого;
- **важно** — заметно улучшает самостоятельность;
- **можно отложить** — не блокирует v1.0.

Затем исправляются блокеры и важные замечания. После этого запускается новое
независимое ревью. Если ревьюер снова говорит `ниже уровня`, цикл продолжается.

## Критерий остановки

Цикл можно остановить, когда ревьюер пишет:

```text
Вердикт: на уровне.
Нет критической категории, которая остаётся ниже первого тома.
Оставшиеся замечания относятся к редактуре или необязательным расширениям.
```

Если остаётся хотя бы один блокер по запускаемому примеру, проверке, практическому зачёту или
самостоятельности главы, v1.0 не готов.
