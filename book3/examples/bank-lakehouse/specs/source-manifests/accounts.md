# Schema Manifest: accounts

## Источник

- Файл: `raw/accounts.csv`
- Роль системы: синтетическая выгрузка счетов из основного банковского контура
- Наблюдаемый grain: одна строка на `account_id`

## Наблюдаемые поля

| Поле | Наблюдаемый тип | Примечания |
|---|---|---|
| `account_id` | string | Кандидат в первичный ключ. |
| `customer_id` | string | Синтетический идентификатор клиента. |
| `product_code` | string | Семейство продукта, например текущий счёт. |
| `opened_at` | date-like string | Дата открытия счёта. |
| `balance_rub` | decimal-like number | Остаток в рублях. |
| `status` | string | Статус счёта. |

## Кандидаты ключей

- `account_id` имеет высокий уровень уверенности как ключ строки.
- `customer_id` имеет связь многие-к-одному и не должен трактоваться как grain счёта.

## PII-кандидаты

Прямые PII не наблюдаются. `customer_id` синтетический.

## Заметки о качестве

- `account_id` должен проходить `not_null` и `unique`.
- `customer_id` должен проходить `not_null`.
- Отрицательные остатки требуют явной продуктовой политики до отбраковки.

## Открытые вопросы

- Какие статусы считаются активными для боевой отчётности портфеля?
- Могут ли остатки быть отрицательными для овердрафтных продуктов?
