# Schema Manifest: customers

## Источник

- Файл: `raw/customers.csv`
- Роль системы: синтетическая выгрузка мастер-данных клиентов
- Наблюдаемый grain: одна строка на `customer_id`

## Наблюдаемые поля

| Поле | Наблюдаемый тип | Примечания |
|---|---|---|
| `customer_id` | string | Кандидат в первичный ключ. |
| `birth_date` | date-like string | Чувствительный демографический атрибут. |
| `region` | string | Регион отчётности. |
| `segment` | string | Сегмент клиента. |
| `pii_email` | string | Прямой PII, сохраняется только в staging. |
| `is_resident` | boolean-like | Признак резидентства для отчётного контекста. |

## Кандидаты ключей

- `customer_id` имеет высокий уровень уверенности как ключ строки.

## PII-кандидаты

- `pii_email` — прямой PII и не должен появляться в marts.
- `birth_date` может быть чувствительным; использование ниже по цепочке требует
  явной спецификации.

## Заметки о качестве

- `customer_id` должен проходить `not_null` и `unique`.
- `pii_email` разрешён в staging только для обучения политике PII.
