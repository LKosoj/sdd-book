# Schema Manifest: loans

## Источник

- Файл: `raw/loans.csv`
- Роль системы: синтетическая выгрузка кредитной системы
- Наблюдаемый grain: одна строка на `loan_id`

## Наблюдаемые поля

| Поле | Наблюдаемый тип | Примечания |
|---|---|---|
| `loan_id` | string | Кандидат в первичный ключ. |
| `customer_id` | string | Синтетический идентификатор клиента. |
| `principal_rub` | decimal-like number | Остаток или исходный principal в рублях. |
| `opened_at` | date-like string | Дата открытия кредита. |
| `days_past_due` | integer-like | Просрочка в днях из источника. |
| `stage` | integer-like | Синтетическое поле stage. |

## Кандидаты ключей

- `loan_id` имеет высокий уровень уверенности как ключ строки.

## PII-кандидаты

Прямые PII не наблюдаются. `customer_id` синтетический.

## Заметки о качестве

- `stage` должен трактоваться как поле источника, а не как выведенная методология.
- `principal_rub` не должен быть отрицательным в этом синтетическом наборе.
- `days_past_due` должен быть неотрицательным, если боевой источник не
  определяет семантику корректировок.

## Открытые вопросы

- Боевой `stage` связан с регулируемой методологией или с категорией источника?
- Присутствуют ли закрытые кредиты в источнике?
