# Приложение A. Чек-листы и шаблоны

Шаблоны копируются в учебную рабочую копию по необходимости. Если существующий
документ проекта уже содержит сведения, используйте ссылку вместо дублирования.

## Перед запуском

- [ ] Рабочий каталог и исходные файлы известны.
- [ ] Требование содержит наблюдаемый вход и результат.
- [ ] Границы правки и доступа определены.
- [ ] Команда проверки действует в текущем окружении.
- [ ] Исходный результат сохранён.
- [ ] Лимит времени или попыток записан.
- [ ] Готовое решение не включено в материалы сравнительной попытки.

## task.md: ограниченная задача

```markdown
# Задача
Пользовательский результат:
Входы и ожидаемые ответы:
Действующее требование и его источник:
Разрешённые файлы:
Ограничения реализации:
Проверка и критерий успеха:
Неясные вопросы:
```

Пустое поле — незаполненная часть задачи, а не молчаливое разрешение агенту выбирать
что угодно. Не копируйте шаблон с пустыми критическими условиями в финальную работу.

## AGENTS.md: карта проекта

```markdown
# Назначение
Что делает проект и где находится текущая задача.

## Код и данные
Путь к точке входа, функции и входным данным.

## Проверка
Точная команда, рабочий каталог и смысл её результата.

## Границы
Что разрешено менять, когда нужно решение человека.

## Подробности
Ссылки на действующие предметные документы.
```

Проверяйте поддержку файла выбранным инструментом. Если загрузка не определена,
дайте явное поручение прочитать его. Этот шаблон не задаёт универсальный порядок
приоритетов инструкций для всех продуктов.

## validation.md: подтверждение поведения

```markdown
# Проверка
Требование:
Проверяемый снимок файлов и данных:
Команда или ручной сценарий:
Ожидаемый результат:
Фактический результат:
Статус: подтверждено / нарушено / не проверено
Ограничение проверки:
Ссылка на сохранённый вывод:
```

Если команда не выполнилась, записывайте отказ запуска. Не заменяйте его формулировкой
«поведение нарушено», когда программа не дошла до проверки поведения.

## handoff.md: передача состояния

```markdown
# Передача
Рабочая копия и задача:
Действующие требования и границы:
Изменённые файлы:
Подтверждено: команды, результаты, версия
Осталось непроверенным:
Известный сбой и свидетельство:
Следующий ограниченный шаг:
Вопрос человеку, если есть:
```

## Завершение сессии

- [ ] Изменения просмотрены и соответствуют задаче.
- [ ] Выполненные проверки относятся к текущим файлам.
- [ ] Не выполненные проверки явно отмечены.
- [ ] Условия успешного завершения не подменены лимитом.
- [ ] Следующий читатель видит путь запуска и оставшуюся работу.
- [ ] Git-действия соответствуют правилам проекта, а не шаблону из чужого примера.

## Вердикт оценщика

```markdown
# Ревью
Проверяемая версия:
Материалы, которые были доступны:

| Критерий | Статус | Свидетельство | Что ещё нужно |
|---|---|---|---|
| Заполнить действующим критерием | Подтверждено / нарушено / неизвестно | Файл или команда | Конкретный шаг |

Существенные нарушения:
Замечания вне задачи, требующие отдельного решения:
Ограничения ревью:
```
