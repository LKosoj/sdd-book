# Приложение B. Протокол сравнения

Это учебный протокол, который заполняется **до** запуска серии. Он не содержит
выдуманных результатов. Начальный минимум трёх повторов — учебный компромисс;
сильный вывод на реальном проекте требует большего и более разнообразного материала.

## Вопрос и гипотеза

```markdown
Вопрос: что именно меняется после выбранной настройки?
Гипотеза: наблюдаемый ожидаемый эффект.
Исходный вариант:
Изменённый вариант:
Единственное изменяемое условие:
Что будет считаться опровержением или отсутствием эффекта:
```

Гипотезу можно не подтвердить. Если исходный вариант всегда справляется, это
ограничивает возможность показать улучшение на этой задаче. Выберите представляющую
работу задачу или исследуйте другой показатель; не меняйте вывод задним числом.

## Фиксируем условия

| Условие | Значение, которое заполняет участник |
|---|---|
| Требование | Точный task.md, одинаковый для вариантов |
| Исходные файлы | Сохранённая копия, включая нужные неотслеживаемые данные |
| Проверка | Команда, входы и критерии; одинаковые для вариантов |
| Инструмент | Название и доступная версия |
| Модель | Доступный идентификатор или отметка о неизвестной версии |
| Разрешения | Чтение, правка, команды, доступ за пределами копии |
| Лимиты | Время, попытки, бюджет при доступном контроле |
| Загрузка карты | Автоматическая подтверждённая или явное чтение |
| Материалы рядом | Какие решения и другие копии были доступны |
| Правила исключения | Когда попытка технически невалидна и как это записывается |

## Порядок

1. Создать свежую копию из исходного набора.
2. Начать новую сессию без предыдущих решений и результатов.
3. Передать одинаковое требование и настройки выбранного варианта.
4. Не исправлять результат вручную; подсказки учитывать.
5. Сохранить доступные действия, итог и файлы.
6. Выполнить одинаковую независимую приёмку.
7. Заполнить строку попытки, включая неуспех или остановку.
8. Перейти к следующему варианту, чередуя их порядок.

Если продукт или условия сервиса изменились в ходе серии, обозначьте границу
изменения. Перезапуск той же сессии с памятью прежнего решения не эквивалентен новой
независимой попытке.

## Таблица попыток

| Попытка | Вариант | Подтверждённый успех | Ложное «готово» | Время | Вмешательства | Стоимость | Причина отказа и свидетельство |
|---|---|---|---|---|---|---|---|
| Заполнить после запуска | Исходный / изменённый | Да / нет / не проверено | Да / нет / нет заявления | Измерить | Перечислить | Значение / нет данных | Факт / причина неизвестна |

Не превращайте «не проверено» в успех. При подсчёте доли подтверждённого завершения
заранее определите, какие попытки входят в знаменатель; показывайте также число
непроверенных и исключённых. Неизвестная стоимость не равна нулю.

## Итоговая запись

```markdown
# Сравнение
Задача, варианты и условия:
Подтверждённые завершения: число / число попыток по каждому варианту.
Ложные объявления готовности:
Вмешательства человека:
Разброс времени и доступные расходы:
Исключённые или непроверенные попытки и причины:
Наблюдаемые различия действий:
Альтернативные объяснения:
Вывод только для проверенных условий:
Что нужно проверить дальше:
```

## Исключение компонента

После основного сравнения изменяйте только один компонент за раз. Для изучения
handoff.md нужна задача с передачей между сессиями: короткая одношаговая работа
может вообще не использовать этот механизм.

Не приписывайте ухудшение единственной причине без анализа действий. Не делайте
универсальный вывод о бесполезности компонента по отсутствию эффекта в одной задаче.
Результат помогает выбрать следующий вопрос исследования, а не отменяет диагностику.
